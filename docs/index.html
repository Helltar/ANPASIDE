MIDletPascal

A small Pascal for the phones of the 2000s, the ones with a keypad, a screen 176 pixels wide and Java ME. A program compiles to a MIDlet: a JAR that runs on such a phone, in J2ME Loader, or in the emulator built into ANPASIDE.

This page describes the language as the mp3cc compiler accepts it, routine by routine. Where the original manual says otherwise, the compiler is what is described here.

1From source to a MIDlet

One run of mp3cc compiles one .pas file and writes class files, nothing else:

a programM.class, a subclass of the MIDP Canvas
a unita class named after the unit in lowercase, and a .bsf file with its symbols
a record typeR_0.class, R_1.class and so on

Because the program itself is the canvas, drawing and key handling are part of the language rather than a library. Everything else the compiler only names in its output: the units the program uses, the library classes it calls, and the runtime classes its built-in routines need. Compiling those units, collecting the classes and packing them into a JAR with a manifest is the job of the IDE. In ANPASIDE that is the Run button.

The runtime is a handful of small classes. FW.class goes into every JAR; the others only when a routine needs them, and the reference says which:

Unlike other Pascals

  • A string is not an array of characters. Its first character is at index 0, and characters are read and changed with GetChar and SetChar; s[i] does not compile.
  • A function's result has to be used, as in standard Pascal; Turbo Pascal, Free Pascal and Delphi let a call stand on its own. FormAddString('Hi'); alone is error E432, so assign it: id := FormAddString('Hi');.
  • Parameters are always passed by value, and routines cannot be nested.
  • There are no sets, enumerated types, files, pointers or with.

2Program structure

A program is a header, declarations, and a main block:

program name;

  { constants, types, variables }
  { procedures and functions }

begin
  { statements }
end.

The program line may be left out. Declarations come in any order and any number of blocks. The program runs the main block and ends at its end., with the period.

As in every Pascal, keywords and names are case-insensitive: Begin, begin and BEGIN are one word.

Comments

{ braces }
(* parentheses and stars *)
// to the end of the line
/* C style */

Compiler directives such as {$R+} are read as ordinary comments: the kind of real numbers and of canvas is set by the build, not by the source.

The last five are handles: a program passes them around but cannot look inside. From these, a program builds records and arrays.

Records

type hero = record
  x, y: integer;
  health: integer;
end;

var player, saved: hero;
begin
  player.x := player.x + 1;
  saved := player;          { copies every field }
end.

Assigning a record copies it, so changing saved later leaves player alone. A record cannot hold an array (error E446).

Each record type becomes a class numbered in the order the compiler meets it: R_0, R_1, and so on. The numbers start again with every run unless the build passes the next free one with -r, and ANPASIDE does, so that the record classes of two modules do not overwrite each other in the JAR. One case is still not covered: two units that use each other can end up with the same numbers, so keep record types out of such a pair. The compiler tells record types apart by their number alone, which is why a clash is not caught at compile time and shows up only as a crash on the phone.

Arrays

type board = array[1..8, 1..8] of integer;
var cells: board;
    scores: array[0..9] of integer;
begin
  cells[1, 1] := 0;
  scores[0] := 100;
end.

Each dimension has its own bounds, and there can be any number of dimensions. Arrays are not assigned whole, only element by element (error E443).

The compiler does not check indexes, not even constant ones: x[7] on an array[1..5] compiles. When it runs, the program stops at that line without a message.

const names a value, type names a type, and var declares variables, of a named type or one written out in place. Variables declared outside any routine are global: every procedure and function declared after them sees them.

5Statements

Where a statement has a body, one statement needs nothing around it and several go between begin and end.

Assignment

x := x + 1;

if

if lives = 0 then
  gameOver := true
else
begin
  lives := lives - 1;
  restart;
end;

for

for i := 1 to 10 do
  sum := sum + i;

for i := 10 downto 1 do
  DrawText(IntegerToString(i), 0, i * 10);

while and repeat

while GetKeyClicked = KE_NONE do
  Delay(100);

repeat
  Delay(100);
until GetKeyClicked <> KE_NONE;

repeat
  tick;
forever;

forever in place of until makes a loop that only break, exit or Halt ends. break leaves the innermost for, while or repeat, and is an error outside a loop.

case

case GetKeyClicked of
  KE_KEY2:          y := y - 1;
  KE_KEY8:          y := y + 1;
  KE_KEY4, KE_KEY6: x := x + key - KE_KEY5;   { several labels }
  KE_KEY5:          begin
                      DrawText('fire', 10, 10);
                      Repaint;
                    end;
  KE_STAR:          ;                         { does nothing }
  0..31:            Delay(50);                { a range, both ends included }
else
  x := 0;
  y := 0;
end;

case name of
  'left', 'l': dx := -1;
  'right':     dx := 1;
end;

The value tested is an integer, a char or a string. Labels are literals or constants, never variables; integer and char labels may also be ranges. The first matching arm runs and nothing falls through. The else part takes any number of statements and is optional; without it, a value that matches nothing does nothing.

  • String labels are compared exactly, upper and lower case included.
  • A label that repeats or overlaps another is error E465.
  • In an arm such as 1: if ok then go; else stop, the else after the semicolon belongs to the case, not to the if.
  • break in an arm leaves the loop around the case.

case needs mp3cc 3.5.4, which ANPASIDE ships since 2.5.0. Older compilers stop with E442.

6Procedures and functions

var total: integer;

procedure add(a: integer; b: string);
var len: integer;           { local, made anew on every call }
begin
  len := Length(b);
  total := a + len;
end;

function multiply(a, b: integer): integer;
begin
  multiply := a * b;
end;

function square(x: integer): integer;
begin
  result := x * x;
end;

begin
  add(multiply(2, 3), 'abc');
  total := square(total);
end.

A procedure returns nothing. A function returns the value last assigned to its own name, or to result. exit leaves a routine at once, and in the main block ends the program like Halt.

Parameters are passed by value. var in a parameter list is ignored with warning W436, so a routine cannot change its caller's variables, only globals. Routines cannot be declared inside other routines (error E431), but they can call themselves:

function factorial(n: integer): integer;
begin
  if n <= 1 then
    factorial := 1
  else
    factorial := n * factorial(n - 1);
end;

Two routines that call each other need one of them declared forward first:

procedure b(y: integer); forward;

procedure a(x: integer);
begin
  if x > 0 then b(x - 1);
end;

procedure b(y: integer);
begin
  if y > 0 then a(y - 1);
end;

7Units and libraries

A program can be split into units written in Pascal, and it can call Java through library classes. ANPASIDE also ships three libraries of its own.

Units

unit geometry;

interface
  function square(x: integer): integer;

implementation
  function square(x: integer): integer;
  begin
    square := x * x;
  end;

initialization
  { runs when the program starts }
end.
program game;
uses geometry;
var area: integer;
begin
  area := geometry.square(5);   { or square(5), unless two units share the name }
end.

A unit name has at least three characters; a shorter one is error E454, whose message says two. There is no finalization section.

A unit shares everything in its interface: constants, types, variables, procedures and functions. Its types, unlike the rest, are only found by their full name. With a unit shapes that declares type point = record x, y: integer; end, another module writes var p: shapes.point; a bare point is error E415, even for an alias such as type index = integer.

Libraries in Java

When a program needs something of MIDP that the language does not offer, it can be written in Java as a library class:

// Lib_mylib.java, compiled for CLDC 1.0 and preverified
public class Lib_mylib {
  public static int square(int value) {
    return value * value;
  }
}
program demo;
uses mylib;
var id: integer;
begin
  ShowForm;
  id := FormAddString('5 squared is ' + mylib.square(5));
  Delay(5000);
end.
  • The class has no package, and its name is Lib_ followed by the unit name in lowercase.
  • Only methods declared exactly public static are seen. One that is also final or synchronized is skipped without a word.
  • Parameters and results may be int, String, Image, Command, RecordStore or InputStream, and a method may return void.
  • A library has routines only, no types or variables.
  • The class goes in the project's library folder, libs/ in ANPASIDE, or in the compiler's global one. The project's folder is searched first.

For phone features such as vibration or the backlight, a library needs the Display; the original manual's chapter on advanced features shows how to reach it. A call that exists only in MIDP 2.0 belongs in a try/catch, or the MIDlet crashes on a MIDP 1.0 phone.

Touch

For on-screen buttons held with several fingers, to walk and jump at the same time:

program buttons;
uses Touch;
var w, h, x, y, vy, floor: integer;
begin
  Touch.Init;
  w := GetWidth;
  h := GetHeight;
  floor := h - 120;
  x := w div 2;
  y := floor;
  vy := 0;
  repeat
    { each button follows its own finger }
    if touch_area(0, h - 80, 80, 80) > 0 then x := x - 4;
    if touch_area(90, h - 80, 80, 80) > 0 then x := x + 4;
    if (touch_area(w - 80, h - 80, 80, 80) > 0) and (y = floor) then vy := -15;

    y := y + vy;
    vy := vy + 1;
    if y >= floor then
    begin
      y := floor;
      vy := 0;
    end;

    SetColor(0, 0, 0);
    FillRect(0, 0, w, h);
    SetColor(255, 255, 255);
    FillRect(x, y - 40, 20, 40);
    DrawRect(0, h - 80, 80, 80);
    DrawRect(90, h - 80, 80, 80);
    DrawRect(w - 80, h - 80, 80, 80);
    Repaint;
    Delay(20);
  until false;
end.

Fingers are numbered 0 to 9. The first finger down is 0, and each next one takes the lowest free number. Touch also has every function of Lib_sensor, under the same names, following finger 0. A program moves over by writing uses Touch and Touch.Init where it had Sensor.

The touch_ functions see every finger and the pointer_ functions only finger 0, so they do not mix. A program that checks a rectangle with touch_area and then reads the position from pointer_pressed_x reads the wrong finger as soon as two are down. Take the position from the finger that is inside:

for i := 0 to 9 do
  if (touch_down(i) = 1) and (touch_x(i) >= x) and (touch_x(i) < x + w)
     and (touch_y(i) >= y) and (touch_y(i) < y + h) then
    slot := (touch_x(i) - x) div cell;

Following Nokia, J2ME Loader and ANPASIDE's runtime report more than one finger only to a JAR whose manifest has Nokia-UI-Enhancement: EnableMultiPointTouchEvents, and ANPASIDE adds it to every program that uses Touch. The fingers are told apart through Nokia's com.nokia.pointer.number property, so the JAR works in J2ME Loader too. On a phone without multi-touch every touch is finger 0, and Touch behaves like Lib_sensor.

Sound

The built-in OpenPlayer has a single player, so background music stops for every effect. Sound has eight channels, 0 to 7. Each channel holds one sound and only ever replaces its own: music on one, effects on the others. It needs no initialization.

program game;
uses Sound;
var ok: integer;
begin
  ok := sound_open(0, '/music.mp3', 'audio/mpeg');
  ok := sound_open(1, '/shot.wav', 'audio/x-wav');
  sound_loop(0, -1);
  sound_volume(0, 60);
  ok := sound_play(0);
  repeat
    { the shot starts over at every press, the music plays on }
    if KeyToAction(GetKeyPressed) = GA_FIRE then ok := sound_play(1);
    Delay(20);
  until false;
end.

The loop count and the volume belong to the channel, not to the sound, so a music channel keeps its volume from one track to the next.

A sound that has to overlap itself, such as shots fired faster than the sound lasts, goes on several channels, and sound_play_free plays whichever of them is free. It never loads a sound itself, since loading takes long enough to be heard, so the channels are filled beforehand:

for i := 1 to 3 do ok := sound_open(i, '/shot.wav', 'audio/x-wav');
{ ... }
if KeyToAction(GetKeyPressed) = GA_FIRE then ok := sound_play_free(1, 3);

OpenPlayer still works alongside, as one more sound, and sound_player_volume sets its volume. OpenPlayer starts every sound at full volume, so the call comes after each OpenPlayer. Both functions are there since 2.7.0.

In ANPASIDE's emulator and in exported APKs, Android plays every sound and mixes them, two MIDI files included. It takes MIDI, WAV, MP3, AAC and AMR. A type it does not know, such as audio/ogg, makes sound_open return 0. Whether an old phone mixes sounds at all is up to the phone; one that does not may return 0 from sound_play while another sound plays.

All functions: Sound reference.

Screen

ANPASIDE's emulator and the APKs it exports draw the canvas over the whole screen, under the camera cutout and into the rounded corners. Screen tells how far each of them reaches into the canvas, so that buttons and text stay clear while the game world still fills the screen:

program hud;
uses Screen;
var w, h, l, t, r, b: integer;
begin
  repeat
    w := GetWidth;
    h := GetHeight;
    l := screen_inset_left;
    t := screen_inset_top;
    r := screen_inset_right;
    b := screen_inset_bottom;

    SetColor(80, 160, 255);
    FillRect(0, 0, w, h);                     { the world, edge to edge }
    SetColor(255, 255, 255);
    DrawRect(w - r - 64, t, 64, 32);          { a menu button in the top right corner }
    DrawText('v 1.0', l, h - b - GetStringHeight('A'));
    Repaint;
    Delay(20);
  until false;
end.

The cutout counts as a band along its whole edge, as Android reports it. A rounded corner counts as the distance that brings the corner of a rectangle inside the curve, on both edges it touches. A Pixel 9 held sideways answers 173 on the camera side and 39 on the other three. The values change when the screen turns, so a game that rotates reads them again.

The runtime measures the screen and hands the values out as the system properties anpaside.screen.inset.left, .top, .right and .bottom. Only ANPASIDE answers them; in J2ME Loader and on an old phone every function returns 0, which is also correct there.

All functions: Screen reference.

Fps

For a game loop that shows its frame rate and runs at the same speed whatever it draws. fps_limit takes the place of the Delay at the end of the loop:

program dot;
uses Fps;
var x: integer;
begin
  x := 0;
  repeat
    fps_count;
    x := (x + 2) mod GetWidth;

    SetColor(0, 0, 0);
    FillRect(0, 0, GetWidth, GetHeight);
    SetColor(255, 255, 255);
    FillRect(x, GetHeight div 2, 10, 10);
    DrawText('fps ' + IntegerToString(fps_get), 0, 0);
    Repaint;
    fps_limit(30);
  until false;
end.

fps_limit waits for whatever time the frame has left, not for a fixed time, and counts from when the previous frame was due. A frame at 60 is 16⅔ ms, and the library carries the fractions over, so 60 frames take exactly a second. A loop slower than the limit is not held up, and one that falls behind, after a pause for instance, carries on from the current time instead of rushing to catch up. fps_get counts the frames of the last full second, so the number it shows changes once a second and does not flicker. Everything is integer arithmetic, since phones with CLDC 1.0 have no floating point.

9Real numbers

CLDC 1.0, the Java ME of the early phones, has no floating point types, so real arithmetic is done in software. It is slow and makes the JAR bigger. The build, not the source, chooses one of two implementations:

10Beyond standard Pascal

MIDletPascal accepts a few things that standard Pascal does not:

  • exit and result in routines, as Delphi and Free Pascal have them;
  • forever to close a repeat loop;
  • ushr, also written >>>;
  • // and /* */ comments, and strings in double quotes;
  • raw JVM instructions in a bytecode … end block, with labels.

Most of them were added by Javier Santo Domingo for MIDletPascal 3. mp3cc is the 3.5 compiler ported to Linux and Android, and the port added one thing to the language: case, which 3.5 rejected with E442.

A build that only checks the compiler's messages can miss a failure: if the compiler process is killed, by a bad argument or a binary built for the wrong system, it writes no M.class and no error. A JAR holding nothing but FW.class is the sign. The exit code of mp3cc is its error count, so any other exit code means the process died. ANPASIDE checks both.

Everything is drawn into a buffer the size of the canvas, in the color set by SetColor, and Repaint shows it. The origin is the top left corner; x grows to the right and y down.

Makes the library's canvas the current screen, as Sensor.Init does, and forgets every finger. Call it once, as Touch.Init, before drawing anything.

The number of fingers on the screen right now.

See also touch_down

touch_down

function touch_down(n: integer): integer;

1 while finger n is on the screen, otherwise 0. Fingers are numbered 0 to 9; any other n gives 0.

Example 
for i := 0 to 9 do
  if touch_down(i) = 1 then
    FillRect(touch_x(i) - 10, touch_y(i) - 10, 20, 20);

touch_x

function touch_x(n: integer): integer;

The last x of finger n. It stays where the finger was lifted, so check touch_down first.

See also touch_y

touch_y

function touch_y(n: integer): integer;

The last y of finger n. It stays where the finger was lifted, so check touch_down first.

See also touch_x

touch_pressed

function touch_pressed(n: integer): integer;

1 if finger n has touched the screen since the previous call for that finger, otherwise 0. Unlike touch_down, it does not miss a tap shorter than a frame. Reading it clears it, so read each finger once per frame and keep the result.

Example 
uses Touch;
var i, taps: integer;
begin
  Touch.Init;
  taps := 0;
  repeat
    for i := 0 to 9 do
      if touch_pressed(i) = 1 then taps := taps + 1;
    { ... draw, Repaint, Delay ... }
  until false;
end.

touch_released

function touch_released(n: integer): integer;

1 if finger n has been lifted since the previous call for that finger, otherwise 0. Reading it clears it, as with touch_pressed.

touch_area

function touch_area(x, y, w, h: integer): integer;

The number of fingers inside the rectangle at x, y of size w × h. An on-screen button is held while this is above 0, whichever finger holds it, so several buttons can be held at once.

Example 
{ a jump button in the lower right corner }
if touch_area(GetWidth - 80, GetHeight - 80, 80, 80) > 0 then
  Jump;

Sound

Reached with uses Sound;. Channels are numbered 0 to 7. A call with any other number does nothing and reports failure: 0, or −1 from sound_duration.

sound_open

function sound_open(ch: integer; name, mimeType: string): integer;

Loads the sound name from the JAR into channel ch, 0 to 7, and closes what the channel held before. Returns 1 on success, 0 if the channel, the file or the type is wrong. The types are audio/midi, audio/x-wav, audio/mpeg, audio/aac, audio/mp4 and audio/amr.

Example 
ok := sound_open(0, '/music.mid', 'audio/midi');
ok := sound_open(1, '/coin.wav', 'audio/x-wav');

See also sound_play

sound_play

function sound_play(ch: integer): integer;

Plays channel ch from the start. If it is already playing it starts over, so an effect fired twice cuts its first run short. Returns 1 on success, otherwise 0.

See also sound_play_free

sound_play_free

function sound_play_free(first, last: integer): integer;

Plays the first channel from first to last that holds a sound and is not playing. When all of them are playing, the one started longest ago starts over; a paused channel is left alone. Returns the channel it played, or −1 if none could be played. It plays only what sound_open put there, so a sound that has to overlap itself is opened on every channel of the range. Since 2.7.0.

Example 
{ up to three shots heard at once }
for i := 1 to 3 do ok := sound_open(i, '/shot.wav', 'audio/x-wav');
{ ... }
if KeyToAction(GetKeyPressed) = GA_FIRE then ok := sound_play_free(1, 3);

See also sound_play

sound_pause

procedure sound_pause(ch: integer);

Pauses channel ch; sound_resume continues from the same place. The other channels keep playing.

See also sound_resume

sound_resume

Continues channel ch where sound_pause stopped it. Returns 1 on success, otherwise 0.

See also sound_pause

sound_stop

procedure sound_stop(ch: integer);

Stops channel ch and rewinds it.

sound_loop

procedure sound_loop(ch, count: integer);

How many times channel ch plays in a row, −1 for endlessly; 1 at first. It takes effect at the next sound_play and stays with the channel through sound_open.

sound_volume

procedure sound_volume(ch, level: integer);

The volume of channel ch, 0 to 100; 100 at first. It takes effect at once and stays with the channel through sound_open.

sound_duration

The length of the sound on channel ch in milliseconds, or −1 if it is not known. ANPASIDE's emulator only knows it while the sound plays, and answers 0 before that.

Stops channel ch and frees its sound. The channel can be opened again.

fps_limit

procedure fps_limit(n: integer);

Waits until the next frame is due at n frames per second, in place of a Delay at the end of the loop. It waits only for what the frame has left, so the loop keeps the same speed whatever it draws. Example 
repeat

  Repaint;
  fps_limit(30);
until false;
